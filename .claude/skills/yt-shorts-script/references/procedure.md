# Script Writing Procedure

1. **Extract the claim.** From the topic and angle, write the sharpest one-sentence claim. This becomes the hook. If it needs a qualifier or setup to land, the claim is too complex — simplify it.

2. **Write the HOOK.** 0–5 seconds. Must stop the scroll in the first 2 seconds. Use one of:
   - Contrarian claim: "You're using X wrong."
   - Surprising number: "90% of engineers skip this step."
   - Uncomfortable truth: "Your code review is theatre."
   No setup, no context — just the claim.

3. **Draft the BODY beats.** 3–4 beats for 60s. Each beat is one point (~10–12 seconds of spoken content). Sequence: problem → evidence → fix → proof. Or: problem → insight → implication when there's no fix.
   - Each beat earns its place. If you can cut it and the script still lands, cut it.
   - Use specific numbers, tool names, or real decisions — never generic observations.

4. **Write the CTA.** One line. Options:
   - "Follow for more. Link in bio." — when there's a Substack post to link
   - "Follow. Next one drops [day]." — when building a series
   - Never: "If you found this helpful..." — that's YouTube 2015.

5. **Add timing markers.** Assign seconds to each BODY beat. Count words. Recount after rewrites.

6. **Add SHOW notes** per the format. One SHOW note per SAY line. Specific beats vague: "screen-record: open CLAUDE.md in VSCode, highlight lines 1–10" beats "show code".

7. **Write the 30s cut.** Take the hook (compress if needed), the strongest beat, the payoff beat, and the CTA. Drop the rest. Retiming is mandatory — don't truncate, rewrite.

8. **Run humanizer check** on all SAY lines. Every line must sound like something a person would say on camera. See `references/voice-and-humanizer.md`.
