## During the Session

> Reminders for participants. Read before joining.

### For the designer

- Bring context first; ask for feedback second.
- Don't defend prematurely. Listen to the *whole* point before responding.
- Take notes. You won't remember.
- Ask "say more about that" when feedback is unclear.
- Don't try to address every piece of feedback in the room. Sit with it.

### For reviewers

- **Read the prompt above.** Honor the ask.
- **Lead with why.** "I'd suggest X because Y" — not "X."
- **Be specific.** Vague feedback is unactionable.
- **Distinguish blocking from suggestion from preference.** Use prefixes if helpful.
- **Don't redesign in the room.** The design stays in the designer's hands.
- **Praise what works.** It's information, not flattery.
- **Build on each other's points.** Don't repeat. Reinforce or disagree explicitly.
- **Don't review tired.**

### Severity prefixes (suggested)

When giving feedback, prefix with one of:

- **Blocking** — "I think this is a real problem we should solve before this ships."
- **Strong suggestion** — "I think this could be significantly better with X."
- **Suggestion** — "Have you considered Y?"
- **Preference** — "Personally I'd lean Z, but it's a judgment call."
- **Question** — "Why is this here? I'm not following."

## After the Session

### Designer:
- [ ] Read your notes after a few hours / overnight
- [ ] Sort feedback into: act on, consider, acknowledge but don't act on, reject
- [ ] Reply to reviewers with what you're taking and what you're not (and why)
- [ ] Iterate
- [ ] If significant changes, schedule a follow-up critique

### Facilitator (if applicable):
- [ ] Capture top themes from the discussion
- [ ] Note any unresolved disagreements among reviewers
- [ ] Confirm the next critique date
