**Read filters** (parse filters only — an entry failing one is silently ignored; containment is **not** enforced here but by the path-safety gate below — `install.sh:354-356`, `install.ps1:266-267`):

- `install.sh` `read_manifest` (`install.sh:357-367`) is a line-wise `awk` regex, **not** a JSON parser: it matches `"path": "[^"]*", "sha256": "[0-9a-f]+"` once per line (`install.sh:360`), so it depends on the one-entry-per-line, exact-spacing form above. Drops entries whose sha is not 64 chars or whose path is outside `^[A-Za-z0-9._@+/-]+$` (`install.sh:364`); absolute and `..` paths pass this filter. Output de-duplicated (`sort -u`, `install.sh:366`). Unparseable content yields zero entries (install then treats every file as pre-manifest; uninstall removes nothing but still deletes the manifest).
- `install.ps1` `Read-Manifest` (`install.ps1:268-279`) parses with `ConvertFrom-Json` (`install.ps1:272`); keeps entries where `path` and `sha256` are strings, `sha256 -cmatch '^[0-9a-f]{64}$'` (case-sensitive, so uppercase hex is dropped, as in `install.sh`) and `path -cmatch '^[A-Za-z0-9._@+/-]+$'` (`install.ps1:274`). Unlike `install.sh`, malformed JSON is not read as zero entries: `ConvertFrom-Json` throws (`$ErrorActionPreference = "Stop"`, `install.ps1:42`) and the install or uninstall aborts.

**Path-safety gate** — `safe_rel <root> <rel> <allow>` (`install.sh:422-454`) / `Test-SafeRel` (`install.ps1:213-233`), checked before every write, hook backup and `rm` (`install.sh:969`, `install.sh:983-986`, `install.sh:1061-1064`, `install.sh:1106-1109`, `install.sh:1164`, `install.sh:1175-1176`; `install.ps1:772`, `install.ps1:870`, `install.ps1:920`, `install.ps1:974`). A path passes only if:

- every component matches `[A-Za-z0-9._@+-]` and there are **at least two** components, so nothing at the root is ever touched through this gate — not the manifest, `settings.json`, `hooks.json`, `CLAUDE.md` or `AGENTS.md` (`install.sh:424`, `install.ps1:214`). The doctrine block in `CLAUDE.md` / `AGENTS.md` is written by separate code that does not use this gate (`doc_write` / `Write-BesideBytes`, planned by `doctrine_plan` / `Set-DoctrinePlan` and re-checked by `doc_recheck` / `Assert-DocUnchanged`; see `ConsumerDoctrineBlock`);
- no component is `.` or `..` (`install.sh:425`, `install.ps1:215`);
- the first component is in that root's allowlist: Claude `skills agents commands hooks agentic-os` (`CLAUDE_ALLOW`, `install.sh:1268`; `$ShippedPrefixes`, `install.ps1:185`, check `install.ps1:217`); Codex config `agents hooks` (`CODEX_CONFIG_ALLOW`, `install.sh:1275`); Codex skills root `*` = any first component (`install.sh:428-429`, passed at `install.sh:1328`, `install.sh:1396`). The former `memory` / `ledger` exclusion is gone; the skill-name rule below replaces it;
- **`agentic-os` holds one file:** a path whose first component is `agentic-os` passes only when it is exactly `agentic-os/doctrine.md` (`$DOCTRINE_REL`; `install.sh:432-433`; ps1 `-cne 'agentic-os/doctrine.md'`, `install.ps1:218-219`), so a tampered manifest cannot reach any other file under `<DEST>/agentic-os/`;
- **skill-name allowlist:** for a Claude `skills/<name>/…` path, and for every Codex skills-root path (where the first component is the skill name), `<name>` must be in `SKILL_NAMES` (`install.sh:427-438`) / `$script:SkillNames` (`install.ps1:220-221`; ps1 is Claude-only, so only `skills/<name>`). The set is the union of the tombstoned slugs, the skill directories in this release's `$SRC/skills`, and every `skills/<name>/` in `ReleaseHashesFile` (`install.sh:1271-1274`; `install.ps1:322`, `install.ps1:328`, `install.ps1:332-333`). A tampered manifest therefore cannot reach another vendor's skills;
- no component from the root down to the file, the leaf included, is a symlink (`[[ -L ]]`, which also sees a dangling link, `install.sh:439-444`) — in ps1, a reparse point on **every** component, including ones that do not exist yet: `Test-ReparsePoint` reads `FileInfo.Attributes`, so a dangling link is still seen, and `-1` means nothing exists there (`install.ps1:187-192`, loop `install.ps1:224-228`);
- containment: `install.sh` — when the parent dir exists, its `pwd -P` lies inside the canonical root `ROOT_CANON` (set by `set_root`, `install.sh:404-408`; check `install.sh:445-452`); `install.ps1` — `[System.IO.Path]::GetFullPath` of the joined path must start with `GetFullPath($Root)` plus a separator (`OrdinalIgnoreCase`, `install.ps1:229-232`).

A failing entry is skipped with `skip <rel> — unsafe path (outside the shipped dirs, unusual characters, or through a symlink); not touched` (`unsafe`, `install.sh:490-494`; `Skip-Unsafe`, `install.ps1:235-240`) and is **not** re-recorded in the new manifest (`install.sh:983-986`, `install.ps1:870`). Each skip also increments the unsafe counter (`N_UNSAFE`, `install.sh:333`, `install.sh:492`; `$script:Unsafe`, `install.ps1:169`, `install.ps1:238`) and records the path for the dry-run hook check (`$WORK/unsafe.lst`, `install.sh:493`; `$script:UnsafeRels`, `install.ps1:171`, `install.ps1:239`). On uninstall it is likewise skipped, and the manifest is still deleted (`install.sh:1175-1176`, `install.sh:1193-1194`; `install.ps1:772`, `install.ps1:789-790`).

**Unmodified** — a file is an AgenticOS copy when its on-disk sha `c` equals the manifest sha `o`, **or** equals any earlier release's sha for that same path in `ReleaseHashesFile` (`unmodified`, `install.sh:470-476`, known list from `load_known` `install.sh:456-468`; `Test-Unmodified`, `install.ps1:335-341`, a `$null` `c` is never unmodified, `install.ps1:338`). So a CRLF conversion is not an edit. ps1 reads and writes the file as ISO-8859-1 (`$Latin1`, `install.ps1:534`; `Read-Latin1` `install.ps1:579`; `Write-BesideBytes` `install.ps1:595-613`; `Get-TextSha` `install.ps1:543-546`), so every byte round-trips and the hash matches `install.sh`'s.

**Shipped-block check.** A block is AgenticOS's only if its LF-normalised sha is a block AgenticOS has shipped; a manifest record is **not** proof, because in project scope the repository ships the manifest (`install.sh:689-690`). `install.sh` `doc_known_block <sha>` (`install.sh:654-662`) succeeds when the sha equals the current `DOC_BLOCK_SHA` (`install.sh:659`), or, on a non-Claude (Codex) run only, when `DOC_KNOWN_FILE` exists and holds the sha as a whole line (`grep -qxF`, `install.sh:660-661`). `DOC_KNOWN_FILE` is `$REPO_ROOT/assets/consumer/doctrine-block-shas.txt` (`install.sh:1282`; format in `ConsumerDoctrineBlockShas`). Claude accepts only the current block, since the Claude body never changes. ps1 is Claude-only and compares `Get-CurBlockSha` with `$script:DocBlockSha` only; it does not read the known-shas file (`install.ps1:643-647`). Used by the plan (`install.sh:691`), by the install-time update / refresh choice (`install.sh:850`; ps1 `install.ps1:705`) and by the uninstall re-check right before writing (`install.sh:908`; ps1 `install.ps1:720`).

**Crash rollback** (install, mode `write`, real run). It covers a stop between the doctrine edit and the manifest that records it (disk full, kill, Ctrl-C). Without the record, a re-run would refuse the block and uninstall would leave it, so the edit is undone rather than recorded first (`install.sh:860-865`; ps1 `install.ps1:964-966`).

- **Arm** — `doc_arm_rollback <target> <new content>` (`install.sh:866-873`) runs right before `doc_write` (`install.sh:817`, `install.sh:857`). When the target exists it copies its current bytes (`cp -p`) to `$WORK/doctrine.pre` and sets `DOC_ROLLBACK_PRE` to the sha256 of the target before the edit; otherwise it creates the marker `$WORK/doctrine.pre.absent` and sets `DOC_ROLLBACK_PRE=absent` (`install.sh:867-871`). It then sets `DOC_ROLLBACK` to the sha256 of the content about to be written (`install.sh:872`). Both start as `""` (`install.sh:603-604`).
- **Disarm** — `write_manifest` sets `DOC_ROLLBACK=""` right after it moves the manifest of `DOC_MF_ROOT` into place (`install.sh:397`). For Claude that is `sync_finish` (`install.sh:1375`) after `doctrine_apply` (`install.sh:1374`). For Codex it is the config-root `sync_finish` (`install.sh:1413`), which runs after the skills-root `sync_finish` (`install.sh:1412`), so a failure in the skills root also triggers the rollback. The disarm does not depend on whether a `doctrine` line was written (in project scope none is).
- **Fire** — the `cleanup` EXIT trap (`install.sh:186-199`, set `install.sh:200`), when `doc_rollback` is defined, first sets `trap '' INT TERM HUP` and then runs `( set +e; doc_rollback )` in a subshell (`install.sh:191-194`), so nothing in the rollback (a failed write, `doc_recheck`, a second Ctrl-C) can stop the cleanup. If that subshell returns non-zero it prints `Warning: could not restore <DOC_TARGET>; delete the lines between the AgenticOS doctrine markers by hand.` to stderr (`${DOC_TARGET:-the doctrine target}`, `install.sh:193`). Then it always removes `TMP`, `WORK` and every `PREFLIGHT_DIRS` entry (`install.sh:195-198`). `doc_rollback` (`install.sh:875-894`) returns 0 at once unless `DOC_ROLLBACK`, `DOC_TARGET` and `WORK` are all non-empty (`install.sh:880`). It returns 0 silently when the edit never landed: pre-state `absent` and the target still absent (no file, no link), or the target a regular non-link file whose sha equals `DOC_ROLLBACK_PRE` (`install.sh:882-883`). If the target is a symlink, is not a regular file, is hard-linked (`find -links +1`) or its sha differs from `DOC_ROLLBACK`, it prints `Warning: the install stopped before recording the doctrine block in <f>, which has changed since (or is now a link); left as it is.` to stderr, changes nothing and returns 0 (`install.sh:884-887`). Otherwise it restores: `rm -f` the target when the pre-state is `absent`, else `doc_write "$WORK/doctrine.pre"` over it; either returns 1 on failure (`install.sh:888-892`), which gives the cleanup warning above. On success it prints `The install stopped before recording the doctrine block, so <f> was restored to how it was before this run.` to stderr (`install.sh:893`). The rollback does not change the installer's exit status.
- **Signals** — right after `trap cleanup EXIT`, `install.sh` sets `trap "trap '' INT TERM HUP; exit 130" INT`, `trap "trap '' INT TERM HUP; exit 143" TERM` and `trap "trap '' INT TERM HUP; exit 129" HUP` (`install.sh:204-206`; comment `install.sh:201-203`). A first INT, TERM or HUP therefore ignores any further INT / TERM / HUP and then exits with 130 / 143 / 129 through the EXIT trap, so `cleanup` (rollback, then temp-dir removal) runs with those signals already ignored: a second Ctrl-C, or the TERM that `timeout` forwards, cannot cut the doctrine rollback or the temp cleanup short. That exit status (130 / 143 / 129) is what the caller sees. SIGKILL cannot be trapped, so a killed installer neither rolls back nor removes its temp dirs, and a doctrine edit made before the kill stays on disk without its manifest record.
- Modes `handsoff`, `current` and `optout`, dry runs, and uninstall (`doctrine_remove`) never arm it.
- **ps1** — `$script:DocWritten` (sha of what `Install-DoctrineBlock` wrote) and `$script:DocPre` (the target's text before that write, `$null` when it did not exist), both initially `$null` (`install.ps1:539-540`). Both are set right before `Write-BesideBytes`: on create, `DocPre = $null` and `DocWritten = Get-TextSha $DocBlockLf` (`install.ps1:686`); on add / update / refresh, `DocPre = $text` and `DocWritten = Get-TextSha $new` (`install.ps1:712`). `$manifestLanded = $false` (`install.ps1:967`), then a `try` runs `Install-DoctrineBlock`, the removals loop, `Remove-EmptyDirs` and the non-dry-run `Write-Manifest`, and sets `$manifestLanded = $true` (`install.ps1:968-981`). Its `finally` (`install.ps1:982-1001`) acts only when `$manifestLanded` is still `$false` and `$script:DocWritten` is set, so it is meant to cover any stop from the doctrine write through the manifest write ("a throw, Ctrl-C", per the comment at `install.ps1:964-966`), but not a killed process. Inside an inner `try`: silent when the edit never landed, i.e. `DocPre` is `$null` and the target is still absent and not a reparse point, or the target is a leaf whose Latin-1 text equals `DocPre` (`install.ps1:985-988`). Restore when the target is a leaf, not a reparse point, `LinkType` is not `HardLink`, and `Get-TextSha (Read-Latin1 $DocTarget)` equals `DocWritten`: `Remove-Item` when `DocPre` is `$null`, else `Write-BesideBytes $DocTarget $script:DocPre`, then `Write-Host` `The install stopped before recording the doctrine block, so <f> was restored to how it was before this run.` (`install.ps1:989-993`). Otherwise `Write-Host` `Warning: the install stopped before recording the doctrine block in <f>, which has changed since (or is now a link); left as it is.` (`install.ps1:994-995`). Any error in that block is caught and gives `Warning: could not restore <f>; delete the lines between the AgenticOS doctrine markers by hand.` (`install.ps1:997-998`). The original exception then propagates (a `finally`, no `catch` at the outer level).

**Uninstall** (mode `write`; `doctrine_remove`, `install.sh:898-933`; `Remove-DoctrineBlock`, `install.ps1:715-743`):

- No backup is taken: on uninstall, mode `write` only follows state `block` **with** an install record, i.e. a block that passed the shipped-block check (`install.sh:736-738`, `install.ps1:662`). Edited (foreign) blocks, and shipped blocks with no record, are left alone in mode `handsoff`. In `install.sh --codex --project` there is never a record, so this path is never taken.
- **Re-check before writing.** Hooks are unregistered between the plan and the removal, so the target is scanned and hashed again first (`doc_scan` + `doc_cur_sha` + `doc_known_block`, `install.sh:905-913`; `Get-DocLines` + `Get-CurBlockSha` compared with `$script:DocBlockSha`, `install.ps1:718-725`). If the markers are no longer exactly one begin and one end with the begin before the end, or the block is no longer a shipped block, `DOC_WHY` / `$script:DocWhy` becomes `changed during the uninstall and no longer holds a block AgenticOS shipped`, the hands-off warning is printed (`⚠ <f> changed during the uninstall and no longer holds a block AgenticOS shipped — AgenticOS leaves it untouched. …`), and nothing is written or deleted (`install.sh:908-912`, `install.ps1:720-724`). It also sets `DOC_MODE=handsoff` / `$script:DocMode = 'handsoff'` (`install.sh:910`, `install.ps1:722`), so the Claude `uninstall_root` (`install.sh:1179-1181`) / ps1 uninstall loop (`install.ps1:775-779`), which runs next, keeps `agentic-os/doctrine.md` that the block left in place may still import. This re-check is about content; `doc_recheck` / `Assert-DocUnchanged` (below) still guard the file type at the write itself.
- Lines begin..end are removed (remainder `install.sh:914`, `install.ps1:727`). When the block is at line 1 **and** the record's `created` is not `true`, one leading separator is dropped: `\r\n` if the remainder starts with it, else one `\n`, else nothing (`install.sh:915-920`, `install.ps1:728-731`). Block at line 1 with `created: true`: the remainder is kept as is, since a file the installer created never got a separator (`install.sh:921-922`, `install.ps1:732`). Block below line 1: the lines before it plus the remainder (`install.sh:923-924`, `install.ps1:734`).
- If the result is empty **and** the record says `created: true`, the file is deleted: `remove <f> (created by AgenticOS, now empty)` (`install.sh:926-928`, `install.ps1:736-738`). Otherwise the file is rewritten: `remove the AgenticOS doctrine block from <f>` (`install.sh:929-931`, `install.ps1:739-741`). A failed `doc_recheck` before the delete, or a failed `doc_write`, exits 1 (`\|\| exit 1`, `install.sh:928`, `install.sh:931`). In `install.sh --codex --project` uninstall never reaches this path (no record, so every block is hands-off), so it never edits or deletes `AGENTS.md`.

**Writes:** `install.sh` `doc_write` (`install.sh:762-776`): `mkdir -p` the parent, `doc_recheck`, `mktemp "<dir>/.agentic-os.XXXXXX"` beside the target, `cp -p` the existing file into it so its mode is kept (a new file gets `chmod 644`), overwrite the temp's content, `doc_recheck` again, then `mv -f` over the target, so a link is replaced, never written through. Each step is checked: `mkdir`, the first `doc_recheck` and `mktemp` failing return 1 at once (`install.sh:767-769`); a failure in the copy / write / second re-check / `mv` chain removes the temp file beside the target (`rm -f "$tmpf"`) and returns 1 (`install.sh:770-775`). When the target is a file, it copies the target's ACL to the temp (`Set-Acl` from `Get-Acl`, only when `$PSVersionTable.PSEdition -eq 'Desktop'` or `$IsWindows`, `install.ps1:605-607`) and its attributes minus `ReadOnly` (`install.ps1:608-609`). **Read rules** (`review-gate-stop.sh:193-205`): for each required reviewer `a`, reads `$root/.claude/reviews/$head-$a.json` and accepts it only when `.agent == a` AND `.head == <current HEAD>` and `.verdict` is in `pass` \| `fix-before-merge` \| `hold` (`review-gate-stop.sh:195-198`). `pass` → satisfied; `fix-before-merge` → satisfied (listed as advisory info); `hold` → block; missing / malformed / mismatched → treated as missing → block (`review-gate-stop.sh:199-204`).
