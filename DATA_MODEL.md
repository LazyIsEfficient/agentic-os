cross-session memory files, the Claude Code Stop-hook memory-extraction
contracts, the PreToolUse general-purpose-ban hook I/O, the reviewer
verdict contract with its SubagentStop capture / Stop gate hooks, and the
installer's consumer-side manifest and hook registration.

**Read filters** (parse filters only — an entry failing one is silently ignored; containment is **not** enforced here but by the path-safety gate below — `install.sh:259-261`, `install.ps1:233-234`):

- `install.sh` `read_manifest` (`:262-272`) is a line-wise `awk` regex, **not** a JSON parser: it matches `"path": "[^"]*", "sha256": "[0-9a-f]+"` once per line (`:265`), so it depends on the one-entry-per-line, exact-spacing form above. Drops entries whose sha is not 64 chars or whose path is outside `^[A-Za-z0-9._@+/-]+$` (`:269`); absolute and `..` paths pass this filter. Output de-duplicated (`sort -u`, `:271`). Unparseable content yields zero entries (install then treats every file as pre-manifest; uninstall removes nothing but still deletes the manifest).
- `install.ps1` `Read-Manifest` (`:235-246`) parses with `ConvertFrom-Json` (`:239`); keeps entries where `path` and `sha256` are strings, `sha256 -cmatch '^[0-9a-f]{64}$'` (case-sensitive, so uppercase hex is dropped, as in `install.sh`) and `path -cmatch '^[A-Za-z0-9._@+/-]+$'` (`:241`). Unlike `install.sh`, malformed JSON is not read as zero entries: `ConvertFrom-Json` throws (`$ErrorActionPreference = "Stop"`, `:36`) and the install or uninstall aborts.

**Path-safety gate** — `safe_rel <root> <rel> <allow>` (`install.sh:309-351`) / `Test-SafeRel` (`install.ps1:190-214`), checked before every write, hook backup and `rm` (`install.sh:423`,`:437-440`,`:515-518`,`:542-545`,`:600`,`:611-612`; `install.ps1:497`,`:583`,`:633`,`:649`). A path passes only if:

- every component matches `[A-Za-z0-9._@+-]` and there are **at least two** components, so nothing at the root is ever touched — not the manifest, `settings.json`, `hooks.json`, `CLAUDE.md` or `AGENTS.md` (`install.sh:323`, `install.ps1:197`);
- no component is `.` or `..` (`install.sh:324`, `install.ps1:198`);
- the first component is in that root's allowlist: Claude `skills agents commands hooks` (`CLAUDE_ALLOW`, `install.sh:701`; `$ShippedPrefixes`, `install.ps1:168`, check `:200`); Codex config `agents hooks` (`CODEX_CONFIG_ALLOW`, `install.sh:708`); Codex skills root `*` = any first component (`install.sh:327-330`, passed at `:726`,`:780`). The former `memory` / `ledger` exclusion is gone; the skill-name rule below replaces it;
- **skill-name allowlist:** for a Claude `skills/<name>/…` path, and for every Codex skills-root path (where the first component is the skill name), `<name>` must be in `SKILL_NAMES` (`install.sh:326-335`) / `$script:SkillNames` (`install.ps1:201-202`; ps1 is Claude-only, so only `skills/<name>`). The set is the union of the tombstoned slugs, the skill directories in this release's `$SRC/skills`, and every `skills/<name>/` in `ReleaseHashesFile` (`install.sh:702-707`; `install.ps1:285`,`:291`,`:295-296`). A tampered manifest therefore cannot reach another vendor's skills;
- no component from the root down to the file, the leaf included, is a symlink (`[[ -L ]]`, which also sees a dangling link, `install.sh:336-341`) — in ps1, a reparse point on **every** component, including ones that do not exist yet: `Test-ReparsePoint` reads `FileInfo.Attributes`, so a dangling link is still seen, and `-1` means nothing exists there (`install.ps1:170-175`, loop `:203-209`);
- containment: `install.sh` — when the parent dir exists, its `pwd -P` lies inside the canonical root `ROOT_CANON` (set by `set_root`, `install.sh:301-307`; check `:342-349`); `install.ps1` — `[System.IO.Path]::GetFullPath` of the joined path must start with `GetFullPath($Root)` plus a separator (`OrdinalIgnoreCase`, `install.ps1:210-213`).

A failing entry is skipped with `skip <rel> — unsafe path (outside the shipped dirs, unusual characters, or through a symlink); not touched` (`unsafe`, `install.sh:387`; `Skip-Unsafe`, `install.ps1:216-219`) and is **not** re-recorded in the new manifest (`install.sh:437-440`, `install.ps1:583`). On uninstall it is likewise skipped, and the manifest is still deleted (`install.sh:611-612`,`:626-627`; `install.ps1:497`,`:509-510`).

**Unmodified** — a file is an AgenticOS copy when its on-disk sha `c` equals the manifest sha `o`, **or** equals any earlier release's sha for that same path in `ReleaseHashesFile` (`unmodified`, `install.sh:367-373`, known list from `load_known` `:353-365`; `Test-Unmodified`, `install.ps1:298-304`, a `$null` `c` is never unmodified). Used for in-release updates, removal of dropped files, and uninstall (`install.sh:454`,`:469`,`:615`; `install.ps1:500`,`:591`,`:606`). So adopting a pre-manifest install (no `o`) **updates** every file that matches some earlier release; only a file matching no known copy is kept as legacy. On the Codex config root, earlier-release paths are compared as-is, so a converted `agents/<name>.toml` never matches a known copy (the list holds `agents/<name>.md`); only `hooks/…` can.
